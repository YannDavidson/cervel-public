# Security Policy

Security and privacy are important to CERVEL.

## Reporting a vulnerability

Please **do not** disclose suspected vulnerabilities through a public issue, discussion, pull request, social post, or other public channel.

Use GitHub's private vulnerability reporting feature for this repository when available. If that channel is unavailable, contact the maintainers privately before sharing technical details.

A useful report includes:

- the affected public artifact;
- reproduction conditions;
- potential security or privacy impact;
- a minimal reproduction when safe;
- whether active exploitation is suspected.

Do not include real credentials, personal data, private knowledge, access tokens, non-public endpoints, or third-party secrets in reports.

## Scope

This policy covers material explicitly published in `cervel-public`. The repository is not a complete production implementation, and publication of an interface does not imply disclosure of the implementation behind it.

Reports involving non-public systems or services should also be submitted privately.

## Coordinated disclosure

Please allow reasonable time for triage, remediation, validation, and coordinated disclosure before publishing vulnerability details.

## Public-repository safety

Public examples and contributions must use synthetic or non-sensitive data and must not contain secrets, private configuration, confidential information, or unreviewed non-public implementation material.

Thank you for helping keep the CERVEL ecosystem secure.
